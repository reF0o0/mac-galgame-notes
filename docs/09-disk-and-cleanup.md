# 09 · 磁盘、备份与清理

装 galgame 这件事真正吃磁盘的不是游戏本身，是**中间产物**：解压到一半的包、
winetricks 下载的运行时、装补丁前留的快照。这一节把实测数字、备份策略和
几个「删了会后悔」的坑记下来。

## 实测占用

同一台机器上 7 部作品的真实数据（`du -sh`，2026-10 实测）：

| 位置 | 占用 | 说明 |
|---|---|---|
| `~/Games` | 43 G | 7 部游戏本体 |
| `~/Applications/Sikarugir` | 10 G | 7 个容器，平均 1.5 G/个 |
| `~/.cache/winetricks` | 3–13 M（清理后） | 装运行时的下载缓存，装完可清 |
| 系统盘 | 460 G 总，已用 184 G，剩 253 G | 还能再装好几部 |

游戏本体按作品差异很大：2D 纯文字作品 1.5 G 起（《可塑性记忆》），带大量
语音和影片的能到 12 G（《千恋＊万花》）。**容器大小和游戏大小无关**——一个
装好运行时的空容器就是 1.3–1.6 G，装十个游戏也是十个 1.5 G 的容器，因为
游戏本体是通过软链接引进去的，不复制。

单部作品明细：

```
千恋＊万花              12 G
アマカノ3               11 G
灵感满溢的甜蜜创想       7.8 G
不败世界与终焉之花        4.4 G
ATRI                    3.9 G
与奴隶的生活             2.8 G
可塑性记忆              1.5 G
```

## 备份策略：快照代替后悔

真正的原则只有一条：**装 winetricks、换渲染后端、上原生组件这类会改容器的操作，
之前先整瓶复制一份。**

```bash
cd ~/Applications/Sikarugir
# 装原生 quartz 之前
cp -R 灵感满溢的甜蜜创想.app 灵感满溢的甜蜜创想.app.bak-装quartz前

# 折腾完确认游戏能进、影片能播，再删快照
mv 灵感满溢的甜蜜创想.app.bak-装quartz前 ~/.Trash/
```

一个容器 1.5 G，快照一份的代价是十几秒和 1.5 G 空间，比「装崩了从头再来」便宜
太多。装 winetricks 组件、替换 `dll`、改注册表之前都值得先拷一份。

游戏存档的备份和回滚单独写在 [08-saves.md](08-saves.md)，那个比容器快照更要紧。

### 坑：不要把快照命名成 `.bak-quartz` 这种结尾

macOS 判断一个目录是不是 app bundle，看的是**扩展名**。`X.app` 是 app，
`X.app.bak-装quartz前` 不是——但它的**子目录**里还躺着一个真的
`Contents/Configure.app`（容器自带组件）。系统会把这个内层 bundle 当成一个
独立的 app 扫描，Spotlight 里就多出一条 `Configure.app`，看起来像"凭空多了一个
容器"，找半天找不到它在哪。

验证方式：

```bash
mdfind "kMDItemFSName == 'Configure.app'"
```

如果列出来的是某个 `.bak-xxx` 目录里的路径，那就是它，不是新容器。
**每个容器自带的 `Contents/Configure.app` 是正常组件**（右键容器 → 显示包内容
能直接看到），不是多余的容器，别删。

想避免这个困惑，快照目录名别以 `.app` 开头，或者干脆建在容器目录外面。

## 什么时候能删什么

删下载包之前，先把**解压码、来源、真实归档格式**记到一个仓库外的私有文件里。
包一删，密码就再也找不回来了——尤其是那种伪装成视频、尾部拼包的归档，重下一次
的成本很高。

| 目录 | 什么时候删 | 风险 |
|---|---|---|
| `~/.cache/winetricks/*` | winetricks 组件装完、游戏验证通过后 | 无，下次装会重新下 |
| 解压时的中间产物 | 解完包、游戏验证能跑后 | 无 |
| `~/Downloads/*.rar`、`*.mp4` 安装包 | 装完、解压码记进凭据文件后 | 无 |
| `.bak-*` 容器快照 | 改造确认没问题后 | 无（前提是确认过） |
| `movie_原版VC1备份/` 等原版备份 | **先想清楚** | 见下 |

### 坑：原版影片备份可能是唯一副本

《灵感满溢的甜蜜创想》里有个 `movie_原版VC1备份/`（367 M）。为了修启动崩溃，
原版 VC-1 影片被替换过，这个备份目录就是**唯一还留着原档的地方**。一旦删掉
下载包，想再拿回原版影片就只能重下整个游戏。删除这类目录前先问：原始下载包里
还有没有？如果下载包已经删了，这个备份就是最后一份。

同理，《アマカノ3》有 `原始文件备份/` 和 `补丁文件备份/`，删之前确认游戏当前
状态是你要的。

## 解压缓存

解大包（尤其是几十 GB 的整合版）时，中间产物可能到 20 G 以上。曾经出现过解压
过程中系统盘瞬间少 26 G 的情况——不是游戏变大，是解压器把整个归档展开到了临时
目录。

处理方式：解压前先 `df -h` 看一眼剩余空间，解完立刻把中间产物移废纸箱再清空。
**废纸篓不清空不会释放空间**——移进 `~/.Trash` 只是"标记待删"，空间还在，
要在 Finder 里点"清空废纸篓"才算数。

## 完整卸载

想彻底删掉 Sikarugir 相关的一切：

```bash
# 1. 容器（游戏本体在 ~/Games，不受影响）
mv ~/Applications/Sikarugir ~/.Trash/

# 2. 应用数据
mv ~/Library/Application\ Support/Sikarugir ~/.Trash/

# 3. 用 Homebrew 装的 cask
brew uninstall --cask sikarugir

# 4. 清空废纸篓，空间才真正释放
```

卸载容器不会碰 `~/Games`——游戏本体一直放在容器外面，这是这套布局的一个附带
好处：容器随时可以推翻重建，游戏不用重新解压。

## 一句话原则

游戏本体是资产，容器和缓存是耗材。**耗材放手删，资产动之前先备份、先确认它是
不是唯一一份。**
